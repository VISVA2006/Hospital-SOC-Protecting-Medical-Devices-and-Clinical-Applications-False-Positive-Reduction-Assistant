## 1. Project Overview

In a hospital Security Operations Center (SOC), analysts face overwhelming volumes of security alerts generated by clinical devices (e.g., infusion pumps, ventilators, patient monitors, MRI/CT scanners) and healthcare workstations. The vast majority (>70%) of these alerts are repetitive false positives (routine vulnerability scans, HL7 burst messages, maintenance reboots). This leads to **severe analyst alert fatigue**, increasing the risk of missing critical threats.

The **Hospital SOC False-Positive Reduction Assistant** is an end-to-end, defensive cybersecurity prototype designed to safely filter repetitive false positives while strictly **preserving novel and dangerous attacks** targeting life-critical clinical assets.

> [!IMPORTANT]
> **Defensive Cybersecurity Prototype Notice:** This project uses 100% synthetic, clinically modeled telemetry. It does NOT connect to real hospital networks, live patient databases, or physical medical equipment.

## 2. Key Features

- **Synthetic Clinical Data Generator**: Generates $\ge 5,000$ realistic alerts with genuine clinical telemetry (Baxter Infusion Pumps, Dräger Ventilators, Philips Monitors, Siemens MRI, GE CT Scanners) with realistic imbalance (70.5% FP/Benign, 19.6% True Threat, 9.8% Investigation).
- **Event Integrity Layer**: Reconciles duplicate event storms, records network latency on delayed events, and re-sequences out-of-order streams into strict chronological order.
- **Rule-Based SOC Baseline**: Models conventional threshold rules for head-to-head empirical comparison.
- **Machine Learning Triage Engine**: Compares Logistic Regression, Decision Tree, and Random Forest, prioritizing **Recall and minimum False Negative Rate** over raw accuracy.
- **Novel Threat Protection**: An **Isolation Forest** anomaly detector flags novel attack vectors, ensuring unseen patterns are never automatically suppressed.
- **Clinical Safety Guardrail**: A deterministic clinical safety policy mandates that critical medical devices (Ventilators, Infusion Pumps) exhibiting unusual network or temporal telemetry can **never be auto-suppressed**.
- **Explainable AI (XAI)**: Generates clear, multi-bullet evidence explaining every recommendation (device profile, scanner status, anomaly score, port deviations).
- **Human-in-the-Loop & Feedback Learning**: Enables SOC analysts to confirm dispositions or record overrides with structured justifications, feeding a periodic retraining pipeline.
- **Interactive Streamlit Web Workspace**: Complete 5-tab dashboard for SOC analysts, managers, and incident responders.
- **Adversarial Verification Suite**: 8 automated test cases covering flood deduplication, out-of-order sequencing, delayed arrival, and model deception attacks.

## 7. Execution Workflow

Run the entire pipeline from scratch using the following simple commands:

```bash
# Step 1: Generate synthetic clinical dataset (5,000+ alerts)
python src/data_generator.py

# Step 2: Clean and preprocess data with audit logging
python src/preprocessing.py

# Step 3: Train models, select the safest classifier, and fit Isolation Forest
python src/train_model.py

# Step 4: Run evaluation experiments and generate visualization charts
python src/evaluation.py

# Step 5: Execute unit and adversarial test suite
pytest tests -v

# Step 6: Launch the Streamlit interactive dashboard
streamlit run app.py
```

## 9. Adversarial Test Cases (All 8 Passed)

1. **TEST-01 (Normal False Positive):** Known vulnerability scanner during maintenance window $\rightarrow$ correctly classified as `LIKELY_FALSE_POSITIVE` (91% confidence).
2. **TEST-02 (Real Suspicious Alert):** External brute force SSH attack against PACS server $\rightarrow$ flagged for `INVESTIGATE / ESCALATE` (99% threat prob).
3. **TEST-03 (Novel Threat on Critical Asset):** Infusion pump communicating with unseen external C2 IP over custom port $\rightarrow$ safety layer overrides and forces `INVESTIGATE`.
4. **TEST-04 (Duplicate Flood):** 10 consecutive identical events $\rightarrow$ 1 logical event emitted; 9 duplicates suppressed.
5. **TEST-05 (Out-of-Order Delivery):** Scrambled events (10:05, 10:01, 10:04, 10:02, 10:03) $\rightarrow$ strictly re-sequenced in chronological order (10:01 to 10:05).
6. **TEST-06 (Delayed Critical Event):** Critical ventilator alert generated at 10:01 and delivered at 10:10 (540s delay) $\rightarrow$ processed correctly with latency tag.
7. **TEST-07 (Model Deception Attack):** Adversary crafts alert mimicking low-severity scanner on a Ventilator $\rightarrow$ Clinical safety rule detects critical asset + unusual telemetry and blocks auto-suppression.
8. **TEST-08 (Batch Deduplication):** Multi-alert batch deduplication preserves unique events without corruption.

## 11. Safety Disclaimer and Limitations

- **Synthetic Environment:** All data, IP addresses, asset tags, and incident records are purely synthetic. No real clinical patient health information (PHI) or real hospital devices were accessed.
- **Human-in-the-Loop Requirement:** The system is an assistant, not an autonomous incident closure authority. High-criticality devices require human analyst confirmation.
